# Desktop-first claim and support routing is part of flagship quality

Date: 2026-04-11
Audience: `chummer6-hub`
Status: injected fleet feedback

## Summary

Hub must support the flagship desktop route without turning it into browser ritual.
The desktop product promise is not satisfied if account, claim, support, and restore flows feel like a web detour.

## Required changes

* Keep claim/install/support flows desktop-first and boring.
* Minimize manual copy-paste or browser ritual where the product can hand off directly.
* Ensure restore and post-claim continuation return to the real desktop workbench rather than a decorative account surface.
* Keep public `chummer.run` surfaces thin and honest so they support the flagship desktop head instead of competing with it.
* Make the primary desktop route explicit everywhere:
  * Avalonia primary when promoted
  * fallback routes clearly labeled as fallback or bounded

## Guardrail

Control-plane polish is only good when it reduces user friction.
Do not add more account/support surface area if it makes the flagship desktop feel less direct.
